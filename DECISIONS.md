## D-005 — Exact-origin routes and robots fail closed (2026-10-14, Codex)
- **Decision:** Enforce exact HTTPS origin for site probes, redirects and manifest routes. Reject payment/authentication/credential paths, userinfo, queries, fragments and non-public DNS. A2A's literal `agent-card.json` path is allowed despite the broad payment-card heuristic. Only explicit service URL fields are extracted; never follow links or emit third-party names/descriptions. Routes stay `discovered` because GET success is not task success.
- **Alternatives considered:** registrable-domain redirects (including www), taking endpoints from directories, executing page scripts or following arbitrary manifest links.
- **Why:** The user explicitly requires same-origin only. This deliberately skips common www redirects rather than silently widening trust. Robots is checked first and again per target path, with longest-match Allow ties, separate training/user-triggered results, ≤10 site requests and ≥1-second spacing. 404/410 permits crawling; other policy failures/challenges/truncation fail closed. Blocks, server errors and challenges end the site's crawl.
- **Evidence / paths checked:** [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html); [A2A current discovery](https://a2a-protocol.org/dev/specification/) uses `/.well-known/agent-card.json`; [legacy A2A](https://a2aproject.github.io/A2A/latest/specification/) described `/.well-known/agent.json`, labelled legacy here; [llms.txt proposal](https://llmstxt.org/) uses `/llms.txt`; [schema.org Product](https://schema.org/Product). The requested `/.well-known/mcp/server.json` and `/.well-known/mcp.json` are compatibility probes: current [official MCP discovery documentation](https://blog.modelcontextprotocol.io/posts/2026-07-28/) describes `server/discover`, and no universal manifest path was verified in official docs. Do not label those paths official standards.
- **UA provenance/licence:** Small frozen subset from [ai.robots.txt robots.json](https://github.com/ai-robots-txt/ai.robots.txt/blob/main/robots.json), [MIT licence](https://raw.githubusercontent.com/ai-robots-txt/ai.robots.txt/main/LICENSE), notice retained in scanner/NOTICE. No Known Agents feed is consumed.
- **RDAP:** User-authorized public registration lookup through [rdap.org bootstrap](https://about.rdap.org/) and HTTPS registry redirects with fixed domain query and matching `ldhName`. Registry path prefixes are supported. Only registration age/status is retained, no contact records; no bulk RDAP dataset or unclear-license threat feeds are redistributed.

## D-010 — Confirm public DNS before using the managed gateway (2026-10-14, Codex review fixes)
- **Diagnosis:** Local DNS returns `198.18.0.1` for external hosts (including www.shopify.com and rdap.org); strict validation rejected it before transport, producing HTTP unavailable and RDAP unsafe_redirect across the seed list. An HTTPS request pinned to that gateway with hostname verification enabled returned 200, matching curl. This is synthetic DNS, not a broken HTTP transport.
- **Decision:** Automatically recognize only domain-name HTTPS destinations whose entire local answer set is exactly `198.18.0.1`. Before any target request, require the fixed `https://cloudflare-dns.com/dns-query` resolver, authenticated with normal TLS, to confirm A and AAAA responses are successful, non-truncated, contain at least one address and contain only globally public IPs. Resolver requests are identified PreflightBot GETs, bounded to 5 seconds/64 KiB, and never follow redirects. Only that fixed resolver may bootstrap through the gateway without confirmation. Ordinary public DNS keeps the existing direct pinned connection with no resolver dependency.
- **SSRF boundary:** No general private-IP allowlist or environment switch. Literal gateway IPs, localhost/reserved suffixes, other private IPs, mixed local answer sets, public-DNS private/mixed answers and missing/failed confirmation remain blocked. The transport revalidates and pins local records and preserves the original SNI/Host/certificate check on every site or RDAP redirect. The legacy `--managed-dns` flag remains accepted but no longer bypasses independent confirmation. This supersedes D-007's opt-in exception.
- **Trust/limits:** The managed gateway remains trusted to route HTTPS for the authenticated hostname, and Cloudflare public DNS is an additional trust/availability dependency only in synthetic mode. We cannot attest the gateway's upstream socket address; public DNS confirmation plus end-to-end hostname authentication is the constraint. Split-horizon private-only targets are intentionally unavailable. No TLS disabling, broad benchmark-range exemption or ordinary-host private-target fallback is introduced.
- **Evidence publication:** Copy raw `public-data/scans` to the static site's `/scans/<domain>.json` (under the `/preflight` Pages base). The repository is already public; capped, flagged third-party evidence is available only through explicit MCP get_evidence and remains unsigned/untrusted. Ordinary tool responses retain their existing filters. This supersedes earlier site/scanner notes that static evidence retrieval was absent.
- **Other review fixes:** Use literal-segment KMP robots matching in O(path length + pattern length) per rule; resolve relative Location values against the current URL before the existing exact-origin/path guard; publish the actual Node 20 stdio setup and `mcp/server.js` entry from mcp/README.md.
