# Static scanner implementation plan

Goal: implement the scanner task against CONTRACT.md, specs/verdict-rules.md and specs/threat-model.md using Node 20 ESM and no paid services.

Architecture: dependency-free modules for robots, bounded DNS-pinned HTTPS requests, HTML heuristics, route extraction, deterministic verdicts, signing and publication. A worker pool scans different domains concurrently; each origin remains sequential and rate limited. CONTRACT.md's outer signature envelope takes precedence over the live-response schema's embedded signature shape.

1. Write node:test coverage for robots, injection fixtures, route poisoning, verdict precedence/confidence, signing and hash chains; run red before implementation.
2. Implement those pure modules and verify the suite. Route endpoints require scanner provenance, exact HTTPS origin, no credentials, payment/auth paths or query strings. Persist safety flags until human review; incomplete coverage cannot create GO.
3. Write crawler integration tests for robots failures/disallow, redirects, budget/rate limits and challenge backoff; implement bounded crawler, RDAP and CLI.
4. Add SHA-pinned scheduled workflow with contents/actions permissions, public-data commits and explicit Pages dispatch. Document operation and decisions.
5. Run all tests and a three-seed-domain live scan. Inspect output, append WORKLOG, commit current branch and push origin HEAD.

Review focus: unavailable or misleading robots; off-origin redirects/manifests; hidden/encoded injections; missing RDAP/feeds and sticky safety flags; partial scans must preserve index entries and change-chain integrity.
